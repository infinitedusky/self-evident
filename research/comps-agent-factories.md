# Comparables: autonomous / parallel coding-agent factories and PR-demo tools

As of 2026-10-20. Researched by web search. Confidence is marked on each claim: **[primary]** means the vendor's own page or docs; **[secondary]** means press or an aggregator; **[unverified]** means one secondary source only, conflicting sources, or a figure I could not check. Nothing here is invented. If a cell says "not found", I looked and found nothing.

## 1. The landscape in one paragraph

Parallel cloud agents that open PRs are now a commodity. Every major vendor ships one: Cursor, Devin, Codex, Jules, Copilot, Claude Code, Factory, Replit, Lovable and OpenHands. Desktop orchestrators (Conductor, Sculptor) do the same thing locally with worktrees or containers. Since February 2026, **"the agent runs the app and shows you proof" is also mainstream**. Cursor attaches videos, screenshots and logs to its PRs, and lets you take over the agent's remote desktop. Devin records an annotated video of an end-to-end test. Antigravity produces a "Walkthrough" artifact. Copilot posts screenshots. What nobody ships is a demo **built around the reviewer**: a persistent, clickable preview with **realistic data seeded where real data is missing, and an explicit account of which data is fake**, plus **expected impact against a measured baseline**, plus **telemetry closing the loop after ship**. The demos that exist prove the agent did something. They do not make the case for the change.

## 3. What is commodity (do not compete here)

High confidence:

- **Parallel agents, each in its own sandbox, each ending in a PR.** Every vendor has this. Jules publishes concurrency caps per tier; Cursor runs one VM per agent; Conductor and Sculptor do it locally for free.
- **Agent decomposition of a big ask into chunks.** Factory Missions (milestones, then features, then fresh workers), Replit Agent 4 (parallel copies plus a merge), Capy (Captain plans, Build executes), Kiro and Spec Kit (spec, then tasks).
- **The agent runs the app and attaches visual proof.** Cursor (video, screenshots, logs, remote-desktop takeover), Devin (annotated video), Antigravity (Walkthrough with recordings), Copilot (screenshots), Factory validators clicking through flows, Lovable browser tests.
- **A live preview URL per PR.** Vercel and Railway previews, and Cyrus wiring agent commits to them.
- **AI code review of the diff.** CodeRabbit, Graphite (Cursor), Vercel Agent, Codex Code Review.

## 4. What is differentiated (nobody found doing it)

Moderate confidence. "Not found" is not proof of absence.

1. **The demo is the review unit, and it is a running app with data filled in.** Today's proofs are recordings of the agent's own test run (Devin, Cursor, Antigravity), or a bare preview URL with an empty database (Vercel, Railway). **None of the agent vendors documents seeding realistic data for the demo.** Devin's docs are silent on test data. Railway's guide treats seeding as the user's script. **Correction 2026-10-20: Lightsprint does it, undocumented** — its onboarding defaults every preview to "Sample data: realistic placeholder users, accounts and records" (see `lightsprint.md`). The claim narrows to: nobody found *labels* the fake data in the demo or ties the demo to a hypothesis.
2. **Telling the reviewer which data is fake.** I found no product that labels fabricated fixtures in the demo, so the reviewer knows what the app really computes and what is staged. This is a trust feature, and nobody has it.
3. **Evidence and expected impact attached to the PR.** Every comparable reports what was done (diff, video, logs). None states the hypothesis, the baseline metric, and the predicted change.
4. **An idea-level loop: hypothesis, baseline, small tests, a dashboard per idea, then checking the change against the baseline after ship.** Agent factories stop at merge. Factory emits OpenTelemetry about the *agent's* actions, not the *product's* outcome. Experimentation tools (PostHog, Statsig and the like; outside this file's scope) measure outcomes but do not start from the idea or drive the agent.
5. **Telemetry proposing ideas.** Not found among agent factories.
6. **An agent that pushes back on the idea before it becomes tasks.** Spec tools structure ideas; Factory has you approve a plan. I found no product pitched on challenging whether the idea is worth building.

## 5. Gaps nobody fills, and the threats

- **Gap: review for people who do not read code.** Founders, PMs and designers can judge a working feature with plausible data in it, not a diff or a 90-second agent recording. This is the clearest unoccupied position.
- **Gap: data realism in previews.** Previews boot empty. Production dumps are unsafe (Railway says never). Realistic synthetic data, scoped to what this change needs, is unsolved as a product and per-repo glue today. **Narrowed 2026-10-20:** Lightsprint seeds sample data by default (undocumented, seen in the app). What remains open is data scoped to *this change's scenario* and labelled as fake in the review.
- **Gap: closing the loop from merge to measured outcome.** No agent vendor ties a PR to a metric moving.

**Strongest counterargument (moderate confidence):** Cursor is one feature away. It already has VMs that run the app, video artifacts, remote-desktop takeover, Graphite for review, and an internal 30%+ agent-PR share. Adding "seed demo data" and "a persistent preview link" is incremental for them. Devin's "Test the app" is the same distance away. Differentiation therefore cannot rest on "the PR has a demo". It has to rest on the **idea-to-outcome loop** (pushback, hypothesis, baseline, demo with labeled fake data, post-ship check, telemetry-sourced ideas), which needs product telemetry the coding vendors do not own. The other side of that threat: experimentation and analytics vendors could add agents. PostHog and Statsig agent features were not researched in this file.

**Added 2026-10-20 (Sandy found it): Lightsprint** (https://lightsprint.ai/), "the software factory for your whole team". PMs, designers and ops describe a change in plain English; cloud agents (Claude Code, Codex, Cursor; bring your own API key or **existing Claude/Codex subscription**) build it on the real codebase; **live sandbox preview per task**, automated QA screenshots and recordings, a **"merge readiness score"** (conflicts, security, design-token lint, component registry, contrast, typecheck, dependencies); engineers approve the PR. Linear, Jira, Slack, GitHub, Bitbucket, 1,000+ MCP integrations. Pricing: Free $0 (5 tasks/plans a week, BYO subscription, sandbox preview, GitHub); Pro $40/seat/month (10M credits per seat, multi-repo, automations, shared skills and guardrails, QA recordings); Enterprise custom (mobile app previews, usage analytics, on-prem). **No PostHog, no telemetry or outcome measurement, no idea validation** beyond "pressure-test product plans before you build". **Added later the same day:** previews run on sample data by default (onboarding step; not in the docs — `research/lightsprint.md`). It is the rented middle of our loop and a closer threat than Cursor to the "demonstrate" step for non-engineers; it stops at the merge. Candidate provider for the factory's build module; cheap test: hand it one small Homework Gate change on the free tier.

**Second risk:** Factory's own finding that **broad parallelism underperforms serial work with targeted parallelism** [primary]. A "factory builds chunks in parallel" pitch should expect merge and coherence problems. Replit uses a conflict-resolving merge step for the same reason.
